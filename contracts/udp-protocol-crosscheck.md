## 三、坐标单位与朝向（确认）

- **1 整数单位 = 1/20 m = 5 cm**：位姿 `pos[m]×20`（`udp2lcm.c:424-426`）写入心跳；接收端 `÷20` 回米（`:158-159` 等）。建图网格分辨率 `dparams[0]=0.05`（`udp2lcm.c:97`）。
- 因此 **UDP 整数坐标 ↔ 地图格子是 1:1**（都以 5cm 为单位），App 的 `canvas↔map` 换算可直接拿心跳 x/y 当格索引。
- **朝向 `r` = 度**，范围 [-180,180]（`pos[2] rad ×180/π` 并归一化，`udp2lcm.c:429-433`）。

## 四、心跳 / 保活（确认 + 1 处修正）

- **建连**：紫派首包（`udp.c:31`）捕获手机 IP、启动心跳线程、发 LCM **7**（初参）；**首包不进 parseCmd**，故建图(LCM30)由**后续**的命令 0 触发。
- **急停**：`poll(fds,1,3000)`（`udp.c:77`）3s 无数据 → 向 `wheel_ctrl` 发停（`udp.c:83-84`），不退出循环。**= 契约的 3s 急停**。
- **心跳间隔**：紫派 **500 ms**（`udp.c:121 usleep(500000)`）——契约原写"每 1s"，**已修正为 500ms**。
- **App 侧**：keepalive 至少每 1s 发一次（< 3s）即安全，不受 500ms 影响。

## 五、命令 `'i'`/105 主机 IP 打包（确认精确方式）

App 发 `UDPSendData(105, IP[0], IP[1], IP[2], IP[3])` →
byte1=IP[0]、byte2=IP[1]、byte4=IP[2]（endX 低字节）、byte6=IP[3]（endY 低字节）。
紫派读 `iparams[0..3] = byte[1],[2],[4],[6]`（`udp2lcm.c:266-269`）。

→ **主机 IP 四段在字节 [1, 2, 4, 6]**（不是连续的 3-6）。App 侧实现分布式拉图时按此打包。

## 六、分布式矩形覆盖 107/108（多车协同的机器人级机制）

- `'k'`/107：暂存**对角点 1**（`diag_pt1 = byte3-6`，`udp2lcm.c:326-329`）。
- `'l'`/108：**对角点 2 + robot_id**（`byte1`：0=主机/1=从机，`:330-401`）。
  - 从机(1)：按矩形 `[pt1,pt2]` + 当前位姿规划 **FullRoad 覆盖(LCM 122)** → **分布式跟踪(LCM 123)**。
  - 主机(0)：加载地图(10) → 分布式跟踪(123)。

→ **子区域 = 一个矩形（两个对角点）**，不是"房间顶点多边形"。这直接修正了 `multi-robot-collab.md` 里子区域的表达方式，也说明**机器人级的多车覆盖紫派已实现**，App 只需按 105/107/108 下发。
