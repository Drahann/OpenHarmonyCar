## 摘要

本作品是一台**面向工业场景的自主巡检机器人**，由三名成员从小车硬件接线、电机差速轮控、激光 SLAM 建图、A\* 导航、全覆盖路径规划，到昇腾视觉模型（自采集数据集、自标注、自训练），再到鸿蒙平板控制 App 与车载分布式协同 agent，**全栈自主搭建、不依赖任何 ROS 中间件**。

系统由**三个异构节点**组成，运行在三种硬件与操作系统上，通过**四条经过逐字节对账的契约化链路**协同：

| 节点 | 硬件 / 系统 | 语言 | 职责 |
|---|---|---|---|
| **平板控制端** | HarmonyOS 平板 | ArkTS | 总控 / 规划 / 可视化：建图、选点、路径下发、多机调度、仪表监看 |
| **紫派主控（每台车）** | Purple Pi OH（RK3566 / OpenHarmony 5.0） | C / C++ / Python3 | 激光 SLAM、A\*/D\* 导航、BCD 全覆盖、差速轮控、UDP↔LCM 桥 |
| **香橙派视觉** | OrangePi AI Pro（昇腾 310B NPU） | Python / C++ | 工业仪表实时检测、关键点读数、DeepSeek 报告 |

能力闭环：**激光自主建图 → A\* 单点导航 → 全覆盖遍历 → 多机协同分区 → 边缘视觉读表 → 异常告警与智能分析报告**。整套系统**国产化、自主可控、无"卡脖子"依赖**：OS 是开源鸿蒙、算力是华为昇腾、语言是国产 ArkTS、导航与覆盖算法成员独立实现、视觉模型连数据集都自采集自标注自训练。本作品已**真机跑通完整闭环**。

# 一、目标问题与意义价值

## 1.1 应用领域

本作品面向**流程工业的设备巡检**，典型场景包括：

- **电力**：变电站、配电室的设备状态、刀闸位置、表计（电压/电流/油温/SF₆ 压力）巡检——电力是当前智能巡检机器人最大的应用市场。
- **化工 / 石化**：焦炉车间、储罐区、管廊等高温、高粉尘、强腐蚀气体、易燃易爆的危险区域巡检。
- **轨道交通**：隧道、机房、变电所的设备与环境巡检。
- **仓储 / 厂房**：地面全覆盖巡查、资产盘点、环境监测。

共同特征是"**环境危险 + 设备/仪表密集 + 需要可追溯数据**"。工业巡检是这些行业**安全生产的第一道防线**——发现隐患于未然，是避免停产、事故、人员伤亡的关键环节。

## 1.2 关注与解决的问题

### 1.2.1 传统人工巡检的三类结构性痛点

| 痛点 | 具体表现 | 行业资料佐证 |
|---|---|---|
| **安全风险高** | 变电站高压电场、化工焦炉高温高粉尘强腐蚀气体、辐射区/有毒气体环境，巡检人员长期暴露于风险 | 化工焦炉车间存在高温、高粉尘、强腐蚀性气体，传统人工巡检面临安全风险、检测盲区、数据离散 |
| **效率低、覆盖不全** | 高速生产线让人工点检难以应对；大型流程工业设备数以万计，工作量剧增，存在检测盲区 | 制造业高速产线 + 流程工业大型设备使巡检工作量剧增 |
| **读数主观、数据离散** | 大量现场仍是指针式机械仪表，人工读数主观、疲劳易错（夜间/高位尤甚），纸质/离散记录难形成可追溯数据资产 | 室内巡检机器人可完成红外、局放、表计识别等带电检测，全面替代人工 |

### 1.2.2 智能巡检的价值（行业实测）

- **变电站**：巡检机器人视觉识别仪表读数、刀闸状态，**准确率达 99%、效率是人工的 5 倍**。
- **石化厂区**：AGV 巡检效率是人工的 **4 倍**；经预设最优路径 + 多机协同，某炼油厂将巡检频次从"每日 2 次"提升到"每小时 1 次"、**人力成本下降约 60%**。
- **化工**：机器人代替人员深入高危区，**减少人员在有毒有害、高温高压恶劣环境中的暴露时间**，大幅降低安全事故概率。

> 本作品的"全覆盖 + 多机协同 + 边缘读表 + 数据资产"能力，正是对上述痛点的系统性回应。

## 1.3 实现的目标与基本功能

**总目标**：用一套完全国产、自主可控的技术栈，做出一台可建图、可导航、可全覆盖、可多机协同、可读表告警的工业巡检机器人，并把"复杂机器人系统"收敛到一块平板上**像用地图导航 App 一样简单**的交互里。

**已实现的基本功能（真机跑通完整闭环）**：

1. **零配置设备发现与连接**——局域网广播发现双车 + 香橙派，按回包源 IP 自动收集、点击连接，四态连接状态机驱动命令门控。
2. **激光 SLAM 自主建图**——摇杆探索、墙体随激光实时生长、存图落盘、自动拉取（优先压缩图 ~6× 小）。
3. **A\* 单机导航**——地图栅格选点、A\* 代价分级规划、自主行驶、到达自动判定、轨迹彗尾可视化。
4. **全覆盖遍历**——BCD 牛耕单元分解 / 矩形 zigzag 牛耕 / 最小生成树，框选区域、覆盖足迹与面积/进度实时上图。
5. **多机协同**——鸿蒙软总线共享任务黑板，多车对角矩形分区覆盖、互不重叠，车间独立通道协同避障。
6. **边缘视觉读表**——昇腾 NPU 上 YOLOv5s 检测 + Simple Baselines 关键点几何读数，阈值告警，本地 DeepSeek 趋势/异常报告 + 历史数据资产。

# 二、设计思路与方案

## 2.1 总体设计思路

四条核心设计原则贯穿全系统：

1. **异构分布式、各司其职**——交互可视化、实时控制、NPU 推理三类任务对硬件诉求迥异，放到各自最合适的设备上（平板/紫派/香橙派），再用契约解耦。
2. **契约驱动开发（Contract-First）**——三端代码物理隔离、互不编译依赖，用 `contracts/` 作为唯一事实来源；任何接口改动先改契约再改代码并**逐字节对账**。这让"三人异构协作"不再因接口不一致而集成失败（工业机器人项目集成失败几乎都源于接口不一致）。
3. **视觉链路与导航链路彻底解耦**——网络层（独立 socket）、线程层（独立 WS）、代码依赖层（互不 import）三重隔离，互不打扰。
4. **把机器人做成"像地图 App 一样好用"**——全屏地图打底、浮层操控、分步引导、安全门控。

## 2.2 技术路线与选型权衡

| 选型 | 取代了什么 | 理由 |
|---|---|---|

### 紫派内部 LCM 信道（C/C++ 模块间总线）

| 信道 | 方向 | 用途 |
|---|---|---|
| `HOKUYO_LIDAR` | 雷达→导航 | 激光点集，供 SLAM 建图/定位 |
| `POSE` | →导航 | 位姿输入修正定位；轮控每 15ms 反馈估算坐标 |
| `ROBOT_CONTROL` | 桥/上层→导航 | 功能控制指令（命令号 7/10/20/30/32/122-127） |
| `CURRENTPOSE` | 导航→上层 | 实时当前位姿（也是 App 心跳坐标来源） |
| `PATH` | 导航→轮控 | 路径规划输出（速度、角速度） |
| `wheel_ctrl` | 桥→轮控 | 建图阶段遥控指令 |

> **双链路解耦原理**：视觉链路（④）与导航链路（①②）在网络、线程、代码依赖三层隔离。展开/收起视觉只连断本 WS，导航的保活/控制/建图照常运行，互不阻塞。

## 2.4 通信协议设计

### 2.4.1 UDP 9 字节协议

```
发送 App→紫派 (9字节, 大端/网络序):
┌────┬────────┬───────┬─────────────┬─────────────┬──────┐
│byte0│ byte1  │ byte2 │  byte3-4    │  byte5-6    │byte7-8│
│命令码│方向/号 │ 速度  │ endX int16  │ endY int16  │ 保留 │
└────┴────────┴───────┴─────────────┴─────────────┴──────┘

接收 紫派→App 心跳 (9字节, 大端, 每500ms):
┌────┬───────┬─────────────┬─────────────┬─────────────┐
│byte0│ 保留  │  byte3-4 x  │  byte5-6 y  │  byte7-8 r  │
│=3带坐标│     │ 当前X int16 │ 当前Y int16 │ 朝向(度)    │
└────┴───────┴─────────────┴─────────────┴─────────────┘
```

设计要点：

- **byte0 一字节双关**：取值刻意对齐 ASCII，既是 App 状态枚举也是紫派命令码——`'f'`=102 全路径、`'g'`=103 取消全路径、`'h'`=104 选顶点、`'i'`=105 拉图、`'k'`=107/`'l'`=108 覆盖对角点、`'m'`=0x6d 强制建图。极简且自解释。
- **字节按命令复用**：byte1/byte2 在不同命令下表达运动方向/速度/房间号/robot_id；**cmd105 把主机 IP 四段打进 byte[1,2,4,6]**（复用 endX/endY 两个 int16 的低字节，高字节恒 0）——9 字节做了远超 9 字节的事。
- **坐标单位**：1 整数单位 = 1/20m = 5cm，与地图格子 1:1；朝向 `r`=度 [-180,180]，0°=+X、正角 CCW 朝 +Y。
- **安全设计**：500ms 心跳 + **3s 看门狗急停**（紫派 3 秒未收到任何指令立即令轮控急停防失控，超时值两端契约对齐）；App 至少每 1s 发一次指令（哪怕空指令）保活。

### 2.4.2 零配置设备发现

破解"紫派要先收首包才知 App IP、App 又得先知车 IP"的死循环：

```mermaid
sequenceDiagram
  participant App as 平板
```

## 2.5 关键算法设计原理

### 2.5.1 激光 SLAM 建图与定位

紫派 `Navi` 模块的 SLAM 全自研，核心是**扫描匹配 + 概率栅格 + 粒子滤波**：

```mermaid
graph TB
  L["激光点云 HOKUYO_LIDAR"] --> SM["多分辨率扫描匹配<br/>由粗到细搜最佳位姿"]
  SM --> GE["高斯估计 (协方差/置信)"]
  GE --> PF["KLD 自适应粒子滤波<br/>动态粒子数,抑制累计漂移"]
  PF --> POSE["CURRENTPOSE 实时位姿"]
  SM --> MAP["概率栅格更新 (占据概率, 0.05m/格)"]
  MAP --> SAVE["saveProbMap → defultMap.txt + 同源 zipedMap.txt"]
  POSE --> HB["UDP 心跳回传 App"]
```

- **多分辨率扫描匹配**（`MultiResolutionScanMatcher`）：把当前激光帧与已建地图在由粗到细的多个分辨率上做相关匹配，先粗定位、再细化，兼顾速度与精度。
- **高斯估计 / 协方差**（`gaussestimator/`）：估计位姿不确定度。
- **KLD 自适应粒子滤波**（`particlefilter/KLD`）：按 KL 散度动态调整粒子数，抑制累计漂移。
- **概率栅格**（`map/MapServer`、`Gridmap`）：维护每格占据概率（`MaxOccupied=0.9`、`MinOccupied=0.2`），落盘为 `defultMap.txt`。

**地图落盘格式**（首行 7 值）：

| 字段 | range | resolution | height | width | metersPerPixel | x0 | y0 |
|---|---|---|---|---|---|---|---|
| 位置 | [0] | [1] | **[2]=行数** | **[3]=列数** | [4]≈0.05 | [5] | [6] |
| 含义 | 量程 | 分辨率 | 栅格行数 | 栅格列数 | 每格米 | 最小角世界X(可负) | 最小角世界Y |

数据区：`defultMap.txt` 空格分隔（`-1`障碍/`0`空旷/`2`已覆盖）；`defultMap.txt.txt` 密排（`1`障碍/`0`）。世界↔栅格：`grid=(world−x0)/metersPerPixel`。⚠️ 行列在第 3、4 位，**不是末两个**（末两个是 x0/y0 偏移，误取即"空气图"——真机渲染 bug 根因，已写入契约）。

**强制重建语义（经真机定位的关键接口约定）**：紫派 `cmd0` 在已有图/导航态时被 `Navi.createMap` 忽略、沿用旧图（→ 摇杆在旧图上定位漂移、cmd2 存的还是旧图），App"开始建图"必须发 **`'m'`/0x6d**（`forceNewMap=true`）才会清空旧图/路径/覆盖产物从头建。

```mermaid
stateDiagram-v2
  [*] --> 无地图
  无地图 --> 建图中: 点开始建图(发 'm'/0x6d 强制重建)
  建图中 --> 建图中: 摇杆探索(墙体实时生长)
  建图中 --> 载入中: 点结束建图(发 cmd2 存图)
  载入中 --> 有地图: 拉图成功(优先ZMAP1压缩图)
  载入中 --> 载入中: 轮询直到字节数达标
  有地图 --> 建图中: 重新建图(再发 'm')
```

### 2.5.2 A\* / D\* 路径规划

A\* 规划器 `CAstar`（`Navi/planner/Astarplanner`）：

```mermaid
graph TB
  START["起点(当前位姿)"] --> OPEN["OPEN 表(按 f=g+h 排序)"]
  OPEN --> POP["取 f 最小节点"]
  POP --> GOAL{"到达目标?"}
  GOAL -->|是| PATH["回溯父指针→路径"]
  GOAL -->|否| NB["扩展邻居(getNeighbors)"]
  NB --> COST["代价 = 移动代价 + 栅格状态代价"]
  COST --> C1["FreeSpace: 低"]
  COST --> C2["Near_Obstacle: 中(neardanger/danger)"]
  COST --> C3["Occupied: 不可通行"]
  NB --> VIS["融合视觉墙 visionMap (initVisionMap)"]
  COST --> OPEN
```

- **节点结构**：`Node{state(NEW/OPEN/CLOSED), g, h, f, k, parent...}`；OPEN 表按 key 排序，最大节点数 `MAXNODES=200000`。
- **代价分级**：栅格状态 `FreeSpace/Occupied/Near_Obstacle`，并赋代价 `heighcost(5)/neardanger(10)/danger(15)`，使路径**主动远离障碍**而非贴墙。
- **三种搜索**：A\*（`AStarSearch`）/ D\*（`DStarSearch`，动态重规划）/ BFS（`BFSSearch`）；机器人半径 `SetConfig(radius)` 做膨胀。
- **视觉墙融合**：把视觉识别到的障碍注入 `visionMap` 联合规划。
- **到达判定**（App 侧镜像）：位姿与目标栅格距离平方 ≤ 32 cell²（≈ √32 格 ≈ 28cm）即判定到达。

### 2.5.3 全覆盖路径规划（算法亮点）

**两套算法 + 优雅降级**：

```mermaid
flowchart TB
  S["收到框选矩形 2对角点 + robot_id"] --> CHK{"矩形合法?<br/>x1≠x2 ∧ y1≠y2"}
  CHK -->|否| ERR["报错: 选点错误"]
  CHK -->|是| BCD["首选: BCD 牛耕单元分解<br/>bcdCoverage.buildPathFromGridState"]
  BCD --> OK1{"BCD 成功?"}
  OK1 -->|是| WRITE["写 roadFile.txt(每行 x,y)"]
  OK1 -->|否| ZIG["回退: 矩形 zigzag 牛耕<br/>getsize_forFullRoad 按长边定主轴"]
  ZIG --> OK2{"成功?"}
  OK2 -->|是| WRITE
  OK2 -->|否| FAIL["结束本轮覆盖(不退线程)"]
  WRITE --> TRACK["LCM123 分布式跟踪 按 robot_id 分段执行"]
```

- **首选 BCD（Boustrophedon Cellular Decomposition，牛耕单元分解）**：把框选矩形按障碍切成若干无障碍子单元，在每个子单元内做牛耕往复（来回扫描线），子单元间用 A\* 连接，生成连续覆盖路径 `fullPath[]`。
- **回退矩形 zigzag 牛耕**：BCD 失败时，比较矩形横/纵边长 `xlen/ylen`，谁长以谁为主轴做规则往复扫描；网格步长由安全半径 `safesize` 与 `minsize` 决定。
- **可选最小生成树（MST）**：单车全路径提供"牛耕 / 最小生成树"算法选择（cmd102 的 byte1=算法号 → LCM127 的 algNum）。
- **覆盖线程**（`CoverageThreadProc`，algNum=0 牛耕+D\*）：

```text
while 等待 algNum 就绪:
  清空旧覆盖路径队列
  房间边界 = 自动凸包(autoGetRoomBoundary) or 手动选点(manualGetRoomBoundary)
  初始化覆盖状态图 initCoverageState → 写 tmpcoverageMap.txt
  起点入队
  while 未完成 isFinished:
    方向 direction = 前(0)/后(1)/左(2)/右(3)
    用 D* 在当前方向 detectFrontPlan 规划探测路径
    沿路径牛耕,标记已覆盖格
  输出最终 coverageMap.txt; 路径写 roadFile.txt
```

- **覆盖路径文件 `roadFile.txt`**：每行一个 `x,y`（5cm 栅格单位）；`robot_id=0`(master) 走前半段、`robot_id=1`(sub) 走后半段逆序。

### 2.5.4 差速轮控与里程闭环

```mermaid
graph LR
  PATH["Navi PATH(v,ω)"] --> SOLVE["差速解算<br/>vL=v-ω·d/2<br/>vR=v+ω·d/2"]
  WCTRL["建图期 wheel_ctrl 遥控"] --> SOLVE
```

轮控（`serial/`）订阅 `PATH`（导航 v/ω）或 `wheel_ctrl`（建图遥控），解算左右轮差速经串口下发驱动板；每 15ms 由编码器经 `POSE` 回传位姿估计，与 SLAM 定位互补，形成里程闭环。

### 2.5.5 边缘视觉读数

```mermaid
flowchart TB
  CAM["USB摄像头 /dev/video0"] --> GRAB["抓帧 OpenCV (640×480 YUYV / 1080p MJPG)"]
  GRAB --> YOLO["YOLOv5s 仪表检测 AIPP OM ~21ms<br/>输入[1,640,640,3] NHWC, 输出 bbox+score"]
  YOLO --> ROI["裁剪仪表 ROI"]
  ROI --> KP["Simple Baselines 关键点 OM ~8ms<br/>输入[1,3,256,192] NCHW, 输出[1,4,64,48]热力图"]
  KP --> REFINE["热力图→坐标(亚像素精炼) 4点"]
  REFINE --> READ["几何换算读数"]
  READ --> RENDER["渲染叠加(框+点+读数+FPS)"]
  RENDER --> JPEG["JPEG编码 q=50"]
  JPEG --> WS["WebSocket 推 JPEG + frame_meta JSON"]
```

**4 关键点**：`center`(圆心/轴心)、`pointer_tip`(指针尖)、`zero_mark`(零刻度)、`full_mark`(满刻度)。

**几何法读数**：以圆心为原点、用 `atan2(-y,x)` 转数学坐标系，取指针相对零→满刻度的**顺时针夹角占比**乘满量程：

```
reading = CW(zero→pointer) / CW(zero→full) × 满量程     # 占比 clamp 到 [0,1]
```

不依赖"每块表单独训练分类"。**多表支持**：YOLO 置信度阈值降到 **0.10** + 长宽比(0.6–1.7) + 面积(<85%全图) 过滤误检框，一图多表各自读数（实测一图两块压力表均正确）。端到端性能：YOLO 21ms + 关键点 8ms + 预/后处理 3ms + JPEG 2ms ≈ **34ms / ~29FPS**。

**协同时序**：


- **坐标系按构造对齐**：子机从 master 同一物理起点出发，`cmd5` 加载图时位姿强制归零 (0,0,0)，无需全局重定位、无需操作员点选初始位姿——一个巧妙工程约束消解了多机坐标对齐难题（朝向比位置敏感，起点需把位置+朝向都卡死、顺序出发）。

```
└── Lidar/         # RPLIDAR/LDS 驱动
```

- **udp2lcm 桥**：`udp.c` 绑定 `INADDR_ANY:5001`，首包捕获客户端并启 500ms 心跳线程；发现 ping(`0x06`) 经 `isDiscoveryPing`→`sendDiscoveryResponse` 只回包；主循环 `poll` 3s 超时即发 `wheel_ctrl{0,0}` 急停。`udp2lcm.c::parseCmd` 把 9 字节翻译成 LCM 命令号。
- **地图服务**：`chdir(/data/test)` 后 `python -m http.server :8000` 以 `/data/test` 为 web 根暴露地图（URL 不带前缀）；保存 `defultMap.txt` 后同源生成压缩图 `zipedMap.txt`。
- **分布式拉图（方案B）**：子机 `cmd105`→`cmd124` 用 `wget` 从主机 `:8000` 优先拉 `zipedMap.txt`（解压为 `defultMap.txt`）+ `roadFile.txt`。

## 3.4 应用层实现（平板 ArkTS App）

ArkTS + ArkUI 声明式，关注点分离（model / service / component / pages），去全局化（不再持有全局 canvas context）。

```
app-harmony/entry/src/main/ets/
├── model/        protocol(9字节编解码) / mission(黑板schema) / geometry / mapContour / vision
├── service/      RobotTransport(UDP) / MapService(拉图解析) / FleetMissionService(软总线) / VisionService(WS)
├── component/    MapCanvas(地图+轨迹+覆盖) / Joystick / DeviceList / VideoView / ReadingPanel
├── pages/        Home / Control / Vision / DeviceTrust / SetIP
└── constants/    protocol / theme / motion / icons / vision
```

- **协议编解码**（`model/protocol.ets`）：`encodeSend` 编 9 字节大端缓冲；`encodePullMap` 单独处理 cmd105 的 IP 散列布局（byte[1,2,4,6]）；`decodeReceive` 解心跳。与紫派 `udp2lcm.c` 逐字段对账。
- **地图服务**（`MapService.ets`）：`fetchMapPreferZiped` 优先拉压缩图、非 ZMAP1/失败回退普通图；`parseMap` 统一三种源格式（空格 `-1/0` / 密排 `1/0` / 压缩 `ZMAP1`）归一为栅格 + 障碍包围盒裁剪 + 正方形化；**`decodeZipedRow` 用 BigInt 解 64 位字**（ArkTS number 仅 53 位精度，普通 number 丢高位导致整行错乱）；墙体"水平行程合并"+ max-pool 粗网格 + 平滑矢量等高线优化亚像素渲染。
- **传输层**（`RobotTransport.ets`）：UDP 收发、广播发现、保活节流；`sendBuffer` 支持方案A 平板直发。
- **多机服务**（`FleetMissionService.ets`）：软总线发现 + 入会话 + 黑板读写（`publishMission`/`subscribeMission`），传输层无关（可在软总线受阻时切 LAN socket）。
- **视觉服务**（`VisionService.ets`）：自持 WebSocket、引用计数（PiP+全屏共享一连接，最后一个 release 才真正断开）、退避重连、整段 try/catch 容错（缺字段转 NaN 也不崩，读数显"—"）。
- **页面**：HomePage（发现/连接/模式 chip/互信/视频入口）、ControlPage（建图/导航/覆盖/多机，全屏地图 + 浮层）、VisionPage（全屏识别 + 读数面板 + 报告）、DeviceTrustPage（软总线互信配对）、SetIPPage（手填 IP 兜底）。

### 压缩地图 ZMAP1 编解码

```mermaid
graph LR
  R["普通图 -1/0 行"] -->|"打包 64格/uint64"| Z["ZMAP1 word序列 ~6×小"]
  Z -->|"HTTP 拉到 App"| BI["BigInt 解每 word→64位串"]
  BI -->|"按width截断补零"| G["归一化栅格 1=障碍"]
```

格式：`ZMAP1` magic + 7 值头 + 每行 `rowBitCount wordCount word0...`；障碍格→bit 1，每 64 格打包成无符号 64 位整数（cell0 在最高位 bit63、依次向低位）；解码 `bit=(word[col>>6]>>(63-(col&63)))&1`。解决"~6.5MB 普通图在紫派单线程 server 上 ~47KB/s 拉不完"。

### 覆盖进度估算（App 侧实时）

```mermaid

  HB["心跳位姿(x,y)"] --> STAMP["盖印覆盖足迹 (半径COVER_RADIUS圆盘内格)"]
  STAMP --> CELLS["已覆盖格集合 Set"]
  CELLS --> AREA["面积 = 格数 × 0.0025m²"]
  CELLS --> PROG["进度 = 已覆盖格 / 区域矩形格数"]
  AREA --> HUD["地图右上 CoverageHud"]
  PROG --> HUD
```

# 五、创新与特色

> 按模板限 3–5 项，下列 5 项为本作品最具竞争力的创新与特色。

## 创新一：全栈国产化、自主可控、零"卡脖子"（核心叙事）

从操作系统内核到 AI 算力、从开发语言到核心算法，全链路用国产生态自主实现：**OS = 开源鸿蒙 OpenHarmony 5.0**、**算力 = 华为昇腾 310B NPU（达芬奇架构，模型经国产 ATC 转 OM 原生推理）**、**语言 = 国产 ArkTS + ArkUI**、**分析大模型 = 本地 DeepSeek-R1 蒸馏（不调用任何国外云 AI，数据不出端）**、**硬件 = 成员亲手装配**。在"具身智能量产元年"与"信创自主可控"双重国家战略下，全栈国产化具典型示范意义，是政策最硬的背书。

## 创新二：零 ROS 依赖的全自研机器人算法栈

SLAM（多分辨率扫描匹配 + KLD 自适应粒子滤波 + 概率栅格）、A\*/D\* 导航（代价分级避障 + 视觉墙融合 + 三种搜索）、**BCD 牛耕单元分解全覆盖 + 矩形 zigzag 优雅降级 + 最小生成树可选**、差速轮控、LCM 组播总线**全部成员独立实现**，不使用 ROS 的 move_base/amcl/gmapping/navigation 等任何组件。这与"绝大多数高校机器人项目重度依赖 ROS"形成根本区别，彻底规避对国外开源机器人中间件的路径依赖；视觉模型更是**自采集数据集、自标注、自训练**（YOLOv5s + Simple Baselines + 几何法读数），不依赖现成商用 API。

## 创新三：鸿蒙分布式软总线多机协同 + 契约化异构架构

以**"共享任务黑板（distributedDataObject FleetMission）"**取代"远程拉起 + 一次性快照"的反模式——多车协同是鸿蒙系统原生能力的深度运用；配合**车间独立多播 LCM 协同避障（COOP_AVOID，车↔车直连、不改 9 字节协议）**与**"从同一起点出发→坐标系按构造对齐（cmd5 归零）"**的巧妙工程约束。整个系统采用**异构三节点 + 契约驱动开发（Contract-First）**：三端物理隔离、互不编译依赖，靠 `contracts/` 逐字节对账集成、`integration-qa.md` 异步对接，是一套可复制的系统工程方法论，从机制上根治"集成失败源于接口不一致"。

## 创新四：昇腾边缘视觉 + 本地大模型，数据不出端的智能读表

**两级流水线**（YOLOv5s 检测 → 裁剪 ROI → Simple Baselines 4 关键点 → **几何法换算读数**）在昇腾 NPU 上端到端 ~34ms / ~29FPS；几何法（指针相对零→满刻度的顺时针夹角占比 × 满量程）不依赖"每块表单独训练分类"，且经阈值过滤支持一图多表并行读数。叠加**本地 DeepSeek-R1 蒸馏模型**做趋势/异常分析报告，形成边缘设备上"数据→读数→告警→洞察→数据资产"的完整闭环。对比 Spot 依赖国外云 AI 读表，本作品数据安全与时延双优。

## 创新五：把机器人做成"像地图 App 一样好用"的产品级交互

全屏地图打底、浮层操控的 **Google-Maps 范式控制台**：**零配置广播发现 + 四态连接状态机 + 命令门控**、**两段式武装选点（先选后发、可中途重选，纯 App 侧下发时机、协议不变）**、**覆盖进度上图 HUD（边扫边看）+ 轨迹彗尾 + 覆盖足迹面积**、分步引导文案、底部可收起 peek、PiP 瞥表→全屏形变、统一设计系统（暖纸墨绿克制审美、禁深色禁霓虹）。配合 **ZMAP1 压缩地图（1bit/格 + BigInt 解码）** 解决弱网慢传输。把复杂机器人系统的使用门槛降到工业现场可直接上手。

### C. 坐标系约定

1 单位 = 1/20m = 5cm（与格 1:1）；朝向 `r`=度 [-180,180]，0°=+X，正角 CCW 朝 +Y；原点 = 紫派建图初始位姿（多机时即 master 起点，子机 cmd5 归零到此）；世界↔栅格 `grid=(world−x0)/metersPerPixel`。

### D. 视觉接口要点（WebSocket /ws/video）

交替推送两条消息：① Binary = JPEG 帧（已叠加检测框/关键点/读数/FPS）；② Text = `frame_meta` JSON `{frame_id, fps, inference_time_ms, num_detections, detections:[{bbox,score,keypoints:[{name,x,y,conf}]}], gauge_angles}`。REST：`/api/summary`（实时状态+readings[status:NORMAL/ALARM/UNKNOWN]）、`/api/history`、`/api/thresholds`、`/api/gauge/configs`、`/api/data/report`（DeepSeek）。断开 3s 退避自动重连。

### E. 术语表

SLAM（同步定位与建图）｜A\*/D\*（启发式/动态全局路径搜索）｜BCD（牛耕单元分解全覆盖）｜MST（最小生成树）｜LCM（轻量通信组播总线）｜NPU（神经网络处理器，昇腾）｜软总线（鸿蒙分布式设备互联）｜DDO（distributedDataObject 分布式数据对象）｜ZMAP1（自定义 1bit/格压缩地图格式）｜ATC/OM（昇腾模型转换工具/离线模型）｜AIPP（昇腾输入预处理）。
