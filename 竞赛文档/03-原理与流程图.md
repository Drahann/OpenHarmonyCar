## 2. UDP 9 字节协议原理

### 2.1 字节布局

```
发送 App→紫派 (9字节, 大端):
┌────┬────────┬───────┬─────────────┬─────────────┬──────┐
│byte0│ byte1  │ byte2 │  byte3-4    │  byte5-6    │byte7-8│
│命令码│方向/号 │ 速度  │ endX int16  │ endY int16  │ 保留 │
└────┴────────┴───────┴─────────────┴─────────────┴──────┘

接收 紫派→App 心跳 (9字节, 大端, 每500ms):
┌────┬───────┬─────────────┬─────────────┬─────────────┐
│byte0│ 保留  │  byte3-4 x  │  byte5-6 y  │  byte7-8 r  │
│=3带坐标│      │ 当前X int16 │ 当前Y int16 │ 朝向(度)    │
└────┴───────┴─────────────┴─────────────┴─────────────┘
```

> **byte0 一字节双关**：取值对齐 ASCII，既是 App 状态也是紫派命令码——`'f'`=102 全路径、`'m'`=0x6d 强制建图、`'l'`=108 覆盖对角点2。
> **字节复用**：cmd105 把主机 IP 四段打进 byte[1,2,4,6]（复用 endX/endY 两个 int16 的低字节，高字节恒 0）。

## 3. SLAM 建图原理与流程

### 3.1 建图状态机（App 视角）

```mermaid
stateDiagram-v2
  [*] --> 无地图
  无地图 --> 建图中: 点"开始建图"(发 'm'/0x6d 强制重建)
  建图中 --> 建图中: 摇杆探索(墙体实时生长)
  建图中 --> 载入中: 点"结束建图"(发 cmd2 存图)
  载入中 --> 有地图: 拉图成功(优先ZMAP1压缩图)
  载入中 --> 载入中: 轮询直到字节数达标
  有地图 --> 建图中: 重新建图(再发 'm')
  有地图 --> [*]
```

> **为何必须发 `'m'` 而非 `cmd0`**：紫派 `cmd0` 在已有图/导航态时被 `Navi.createMap` 忽略（日志 `Ignore create map ... force=0`）、沿用旧图 → 摇杆在旧图上定位漂移、cmd2 存的还是旧图。`'m'`/0x6d 走 `forceNewMap=true` 清空旧图从头建。这是经真机定位的接口语义。

### 3.2 SLAM 内部原理

```mermaid
graph TB
  L["激光点云<br/>HOKUYO_LIDAR"] --> SM["多分辨率扫描匹配<br/>由粗到细搜位姿"]
  SM --> GE["高斯估计 + 协方差"]
  GE --> PF["KLD 自适应粒子滤波<br/>抑制累计漂移"]
  PF --> POSE["CURRENTPOSE 实时位姿"]
  SM --> MAP["概率栅格更新<br/>0.05m/格"]
  MAP --> SAVE["saveProbMap → defultMap.txt<br/>+ 同源生成 zipedMap.txt"]
  POSE --> HB["UDP 心跳回传 App"]
```

**概率栅格落盘格式**（首行 7 值）：

| 字段 | range | resolution | height | width | metersPerPixel | x0 | y0 |
|---|---|---|---|---|---|---|---|
| 位置 | parts[0] | [1] | **[2]=行** | **[3]=列** | [4]≈0.05 | [5] | [6] |
| 说明 | 量程 | 分辨率 | 栅格行数 | 栅格列数 | 每格米 | 最小角世界X(可负) | 最小角世界Y |

> **世界↔栅格换算**：`grid = (world − x0) / metersPerPixel`。⚠️ 行列在第 3、4 位，**不是末两个**（末两个是 x0/y0 偏移，误取即"空气图"——真机渲染 bug 根因）。

### 3.3 压缩地图 ZMAP1 编解码

```
ZMAP1                                       ← magic
range resolution height width mpp x0 y0     ← 同 defultMap 的7值头
rowBitCount wordCount word0 word1 ...        ← 每行一条, 共 height 行
```

- 编码：障碍格→bit 1，空旷→bit 0；每 64 格打包成无符号 64 位整数（cell0 在 bit63，依次向低位）。
- 解码：`bit = (word[col>>6] >> (63-(col&63))) & 1`；**必须用 BigInt**（number 仅 53 位精度会丢高位）。

```mermaid
graph LR
  R["普通图 -1/0 行"] -->|"打包 64格/uint64"| Z["ZMAP1 word序列 ~6×小"]
  Z -->|"HTTP 拉到 App"| BI["BigInt 解每个 word→64位串"]
  BI -->|"按width截断补零"| G["归一化栅格 1=障碍"]
```

### 4.2 A\* 代价模型

```mermaid
graph TB
  START["起点(当前位姿)"] --> OPEN["OPEN 表(按 f=g+h 排序)"]
  OPEN --> POP["取 f 最小节点"]
  POP --> GOAL{"到达目标?"}
  GOAL -->|是| PATH["回溯父指针→路径"]
  GOAL -->|否| NB["扩展邻居(8向)"]
  NB --> COST["代价 = 移动代价 + 栅格状态代价"]
  COST --> C1["FreeSpace: 低"]
  COST --> C2["Near_Obstacle: 中(neardanger)"]

```

> 栅格状态分级（`FreeSpace / Near_Obstacle / Occupied`）赋不同代价（`heighcost/neardanger/danger`），使路径**主动远离障碍**而非贴墙。支持 A\*/D\*/BFS 三种搜索，D\* 用于动态重规划。

### 5.2 BCD 牛耕单元分解原理


**覆盖线程伪代码**（`CoverageThreadProc`，algNum=0 牛耕+D\*）：

```text

  清空旧覆盖路径队列
  房间边界 = 自动凸包 or 手动选点
  初始化覆盖状态图 → 写 tmpcoverageMap.txt
  起点入队
  while 未完成:
    方向 = 前/后/左/右 探测
    用 D* 在当前方向规划探测路径
    沿路径牛耕，标记已覆盖格

```

### 8.2 两段式武装选点状态机（本次新增）

