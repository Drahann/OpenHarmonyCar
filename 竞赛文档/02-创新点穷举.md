## 总览：创新的三条主线

1. **🇨🇳 全栈国产化、自主可控、零"卡脖子"**——从操作系统内核到 AI 算力、从开发语言到核心算法，全链路用国产生态自主实现。
2. **⭐ 工程级的契约化异构协作架构**——三个异构节点、三种语言、四条链路，靠 `contracts/` 逐字节对账集成，是一套可复制的系统工程方法论。
3. **⭐ 把"复杂机器人系统"做成"像地图 App 一样好用"**——产品级交互把建图 / 导航 / 覆盖 / 多机 / 读表收敛到一块平板上的分步引导里。

## 一、国产化与自主可控创新（🇨🇳 核心叙事）

> 本项目由成员一手搭建：小车硬件、接线、电源全部亲手装配；SLAM、A\*、全覆盖、轮控全部独立实现；昇腾模型自己找训练集、自己标注、自己训练。这不是"调库拼装"，而是"从零自研"。

- **I-1 ⭐🇨🇳 操作系统国产化**：主控运行**开源鸿蒙 OpenHarmony 5.0**（RK3566），控制端运行 **HarmonyOS 平板**，全程不依赖任何国外操作系统。
- **I-2 ⭐🇨🇳 AI 算力国产化**：视觉推理全部跑在**华为昇腾 310B NPU**（达芬奇架构、20 TOPS INT8）上，模型经国产 **ATC** 工具链转 `.om` 原生推理，不依赖 NVIDIA CUDA / TensorRT。
- **I-3 ⭐🇨🇳 开发语言国产化**：平板 App 与车载 agent 全部用**国产 ArkTS 语言 + ArkUI 声明式框架**开发。
- **I-4 ⭐🇨🇳 零 ROS 依赖的自研机器人栈**：SLAM 建图、A\*/D\* 导航、BCD 全覆盖、差速轮控、通信总线**全部成员独立实现**，不使用 ROS 的 move_base / amcl / gmapping / navigation 等任何组件——这是与"绝大多数高校机器人项目重度依赖 ROS"的根本性区别，彻底规避了对国外开源机器人中间件的路径依赖。
- **I-5 ⭐🇨🇳 视觉模型从数据到部署全自主**：仪表数据集**自采集、自标注、自训练**（YOLOv5s 仪表检测 + Simple Baselines 4 关键点），不依赖任何现成商用 API 或预训练黑盒。
- **I-6 🇨🇳 分析大模型本地化**：用 **DeepSeek-R1-Distill-Qwen-1.5B** 在昇腾上本地生成趋势/异常分析报告，**不调用任何国外云端大模型**（对比 Boston Dynamics Spot 依赖 Google Gemini 云 AI 读表）。
- **I-7 ⭐🇨🇳 国产分布式中间件**：多机协同直接用**鸿蒙分布式软总线**（`distributedDataObject`）做设备发现、可信组网与数据同步，是国产操作系统原生能力的深度运用。
- **I-8 🇨🇳 硬件全自主装配**：小车底盘、电机驱动接线、双雷达（LDS-50C-2 建图 + RPLIDAR A2M8 导航）、串口驱动、电源管理全部成员亲手搭建调试。
- **I-9 🇨🇳 政策精准落点**：契合国务院"人工智能+"意见的"促进开源生态繁荣"与"提升安全能力水平"两项基础支撑，以及信创"自主可控"国家战略。

## 二、系统架构创新

- **A-1 ⭐ 异构三节点分布式架构**：平板（交互）/ 紫派（实时控制）/ 香橙派（NPU 推理）各司其职，每个节点只跑它最擅长的事，三者**物理隔离、互不编译依赖**。
- **A-2 ⭐ 契约驱动开发（Contract-First）**：用 `contracts/` 目录作为三端唯一事实来源（UDP 协议、地图格式、多机协同、视觉 API、LCM 信道），任何接口改动先改契约再改代码，并逐字节对账（含跨端 Q&A 异步对接机制）。这套方法论让"三人异构协作"不再因接口不一致而集成失败。
- **A-3 ⭐ 视觉链路与导航链路三重解耦**：网络层（独立 socket）、线程层（独立 WS）、代码依赖层（不 import 导航服务）三重隔离——展开/收起视觉**不打断**导航的保活/控制/建图。
- **A-4 双多机方案并存可切换**：同时实现"软总线 DDO + 车载 agent"（产品级创新）与"平板直连双车 UDP"（应对硬件 AP 隔离的稳健退路），`FleetMissionService` 设计为传输无关，一键切换。
- **A-5 车载无界面轻 agent**：常驻紫派的 headless ArkTS 节点，以"黑板↔本机 UDP 桥"取代旧"每车装整 App + startAbility 当 RPC"的反模式，与平板共享 UI 无关层（改一处即同源）。
- **A-6 关注点分离的 App 内部架构**：model（协议/任务/几何）/ service（传输/地图/多机/视觉）/ component / pages 分层，去全局化（不再持有全局 canvas context），单例 + 引用计数管理共享资源。

## 三、通信协议创新

- **P-1 ⭐ 9 字节极简定长二进制协议**：单包即一条完整指令，零序列化框架依赖，嵌入式实时控制开销极低、确定性强（对比 ROS topic / JSON / gRPC 的重序列化）。
- **P-2 ⭐ byte0 一字节双关**：命令码取值刻意对齐 ASCII（`'f'`=全路径 102、`'m'`=强制建图 0x6d、`'l'`=覆盖对角点2 108），**同一字节同时表达"App 状态"与"紫派命令"**，极简自解释。
- **P-3 字节按命令复用**：byte1/byte2 在不同命令下表达运动方向 / 速度 / 房间号 / robot_id；cmd105 甚至把主机 IP 四段巧妙打进 byte[1,2,4,6]（复用 int16 字段低字节），9 字节做了远超 9 字节的事。
- **P-4 ⭐ 局域网广播零配置发现**：App 广播 `0x06` 发现 ping，紫派**只回包**（不记客户端、不起心跳、不武装急停），按回包源 IP 自动收集设备——**免手填 IP**，破解"紫派要先知 App IP、App 又要先知车 IP"的死循环。
- **P-5 一码区分异构设备**：车回 `0x06`、香橙派视觉设备回 `0x07`，App 按 byte0 自动分流（车 vs 视觉源），动态 IP 的香橙派也能被自动定位。
- **P-6 安全优先的看门狗设计**：500ms 心跳 + 3s 看门狗急停（3 秒无指令立即停轮防失控），且两端超时值契约对齐。
- **P-7 强制重建图语义对齐**：经真机定位发现 `cmd0` "有图时只当心跳"会被忽略，独立定义 `'m'`/0x6d 强制重建（`forceNewMap`），并写入契约，避免后人踩坑——这是"契约化协作"价值的真实案例。
- **P-8 LCM 内部总线**：紫派内部用基于 UDP 组播的 LCM 串联雷达/轮控/导航，高带宽低延迟，UDP 命令经桥模块翻译成 LCM 命令号。

## 四、SLAM 与建图创新

- **S-1 ⭐ 全自研激光 SLAM**：多分辨率扫描匹配（由粗到细）+ 高斯估计 + KLD 自适应粒子滤波，不用任何现成 SLAM 库。
- **S-2 概率栅格 + 双格式落盘**：0.05m/格概率栅格，空格分隔 `-1/0/2`（普通图）与密排 `1/0`（兼容图）双格式。
- **S-3 ⭐ ZMAP1 压缩地图格式**：1bit/格、每 64 格打包成无符号 64 位整数，~6× 更小，解决"6.5MB 普通图在单线程 HTTP server 上 ~47KB/s 拉不完"的弱网难题。
- **S-4 ⭐ BigInt 精确解压**：App 端用 BigInt 解 64 位字（ArkTS number 仅 53 位精度，普通 number 会丢高位导致整行错乱），并有位序/补零/全障碍用例守护防回归。
- **S-5 双雷达分工**：LDS-50C-2 专司建图、RPLIDAR A2M8 专司导航，各取所长。
- **S-6 地图渲染优化**：墙体"水平行程合并"（同行连续障碍格合并成一条矩形），亚像素地图下消除发丝缝隙、缩放重绘更跟手；max-pool 粗网格 + 平滑矢量等高线取代逐格方块。

## 五、路径规划与全覆盖创新

- **C-1 ⭐ BCD 牛耕单元分解全覆盖**：把框选矩形按障碍切成无障碍子单元、单元内牛耕往复、单元间 A\* 连接，生成连续覆盖路径（首选算法）。
- **C-2 ⭐ 优雅降级**：BCD 失败自动回退矩形 zigzag 牛耕（按长边定主轴），保证"总能扫"。
- **C-3 多算法可选**：单车全路径提供"牛耕 / 最小生成树"两种算法选择。
- **C-4 自动+手动房间边界**：覆盖区域既可凸包自动圈定，也可平板手动选点框定。
- **C-5 ⭐ A\* 代价分级避障**：栅格分 FreeSpace/Near_Obstacle/Occupied 并赋不同代价，路径主动远离障碍而非贴墙；支持 A\*/D\*/BFS 三种搜索 + 视觉墙融合。
- **C-6 D\* 动态重规划**：覆盖探测时反复用 D\* 做方向探测与动态重规划。
- **C-7 到达自动判定**：栅格距离平方 ≤ 32 cell²（≈28cm）自动判定到达，无需盯屏。

## 六、多机协同创新

- **M-1 ⭐ 软总线共享黑板模型**：所有节点常驻同一 `distributedDataObject` 会话，共享 `FleetMission` 任务黑板，反应式读写（谁改谁广播、其余 onChange 响应），取代"远程拉起 + 一次性快照"的反模式。
- **M-2 ⭐ 从同一起点出发→坐标系按构造对齐**：子机用 `cmd5` 加载图时位姿强制归零到 master 起点 (0,0,0)，无需全局重定位、无需操作员点选初始位姿——一个巧妙的工程约束消解了多机坐标对齐难题。
- **M-3 对角矩形分区**：平板为每车划一个轴对齐矩形子区域（2 对角点 + robot_id），各车分区清扫、互不重叠。
- **M-4 ⭐ 车间协同避障（COOP_AVOID）**：覆盖时两车路线交叠，用**独立多播 LCM 通道**（车↔车直连、不经平板、不经软总线）做协同避障，被让车保存目标→停车等待→恢复重下，tie-break 由 robot_id 决定。这是与平板/软总线完全解耦的独立安全通道。
- **M-5 进度实时回写黑板**：各车心跳位姿/进度经 agent 节流写回黑板，平板实时渲染所有车的位置/朝向/进度。
- **M-6 新主"多选点队列"设计**：plan9 后的演进——平板为每车分配多个选点队列、车端复用普通目标点导航逐点执行，路线交汇仍由 COOP_AVOID 兜底。

## 七、边缘视觉与读表创新

- **V-1 ⭐ 两级流水线读表**：YOLOv5s 检测仪表 → 裁剪 ROI → Simple Baselines 4 关键点 → 几何换算读数，端到端 ~34ms / ~29FPS。
- **V-2 ⭐ 几何法指针读数**：以圆心为原点、取指针相对零刻度→满刻度的**顺时针夹角占比**乘满量程，4 关键点（center/pointer_tip/zero_mark/full_mark），不依赖"每块表单独训练分类"。
- **V-3 多表并行**：YOLO 阈值降到 0.10 + 长宽比(0.6–1.7) + 面积过滤剔除误检，一图多表各自读数。
- **V-4 ⭐ 昇腾 NPU 原生推理 + 实时优化**：ATC 转 OM、ACL 上下文独立子线程、帧队列 + 跳帧保实时。
- **V-5 量程标定与物理量映射**：`calib.json` 把读数占比映射到物理量纲（MPa 等）+ 阈值告警（NORMAL/ALARM/UNKNOWN）。
- **V-6 ⭐ 本地大模型分析报告**：DeepSeek-R1 蒸馏模型基于最近 24h 读数做趋势/异常分析，SSE 流式返回，生成时暂停摄像头释放 NPU——边缘设备上的"数据→洞察"闭环。
- **V-7 完整数据资产**：历史读数（最近 600 条）、统计、报告导出（md/txt），形成可追溯的巡检数据资产。
- **V-8 鲁棒容错**：App 侧视觉解析整段 try/catch、缺字段转 NaN，服务端字段异常也不崩（真机加固）。

## 八、人机交互与产品体验创新

- **U-1 ⭐ Google-Maps 范式控制台**：全屏地图打底、浮层操控（顶部状态胶囊 / 右侧缩放 FAB / 底部操作卡 / 左上 PiP），把机器人控制做成地图 App 的熟悉体感。
- **U-2 ⭐ 四态连接状态机**：⚪已发现→🟡连接中→🟢已连接→🔴丢失，每 600ms 由心跳新鲜度刷新、驱动命令门控。
- **U-3 ⭐ 两段式武装选点（本次新增）**：开始选点→地图上只暂存不下发（可中途任意重选微调）→结束选点统一下发 / 取消放弃，未提交前绝不污染紫派状态。纯 App 侧下发时机改动，协议字节/语义不变。
- **U-4 ⭐ 覆盖进度上图（本次新增）**：全覆盖 / 多机模式的覆盖进度从控制栏摘出，做成浮于地图右上角的 CoverageHud（单车进度+面积 / 多车每车一行），边扫边看、不与其它浮层重叠。
- **U-5 行走轨迹彗尾可视化**：各车轨迹按状态配色，软辉光底 + 历史淡痕 + 头部渐亮的"彗尾"观感，覆盖足迹绿色填充 + 面积实时累计。
- **U-6 分步引导文案**：每个模式每一步都有"现在该点哪个"的引导（如"① 选目标点 → ② 开始导航"），降低操作门槛。
- **U-7 底部卡可收起 peek**：默认收起只占一行（摘要+主操作+把手）、地图最大化；点把手展开完整控件（可滚动、按屏高封顶），根治"操作卡向上长遮挡地图"。
- **U-8 设备互信配对 + 手填 IP 兜底**：软总线一次性互信（多机前置）+ 公共 AP/客户端隔离场景的手填 IP 兜底，鲁棒可用。
- **U-9 PiP 瞥表→全屏形变推入**：视觉小窗与全屏共享一条 WS（引用计数），"PiP 放大到全屏再返回"不误断流。
- **U-10 一致的设计系统**：theme/motion/icons 三个单一来源 + SymbolGlyph + 全局动效，暖纸墨绿克制审美、禁深色禁霓虹。

## 九、工程与安全创新

- **E-1 跨端异步对接机制**：`contracts/integration-qa.md` 让"两侧的人和 AI 异步对接"，带日期追加结论/问题，沉淀了 12+ 项对接决策。
- **E-2 离线 mock 联调**：`tools/mock-purplepi`、`tools/mock-orangepi`、`tools/mock-app` 让任一端可在没有其它端时独立联调。
- **E-3 纯逻辑测试守护**：`verify.mjs`（协议/坐标 17/17）、`verify-reconciler.mjs`（黑板决策 9/9）、ZMAP1 位序用例，防回归。
- **E-4 安全优先**：3s 看门狗急停、命令门控（未连不可发）、发现 ping 不武装急停、强制建图避免旧图漂移。
- **E-5 弱网鲁棒**：压缩图 + 回退、退避重连、读超时与传输超时分离、轮询拉图可取消。
- **E-6 显示保活**：紫派 `power-shell wakeup/timeout` 防 OH 默认 30s 息屏影响渲染。
- **E-7 文档与代码同源核对**：演示片文案、色值、协议数字均与 `theme.ets`/`contracts`/`README` 核对一致。
