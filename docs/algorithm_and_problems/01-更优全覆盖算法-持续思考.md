# 更优全覆盖路径覆盖算法 —— 持续思考

> 本文是一份**演进式**的设计笔记：从修好现有算法，到工业级方案，再到面向"双车协同 + 未知/动态环境"的
> 更高目标，逐级抬高。代码不在本文范围，只谈思路、取舍与适用边界。
>
> 现状回顾（详见 `covering_alfor` 仓库 `Navi/planner/`）：`algNum=0` 牛耕法、`algNum=1` STC、
> `algNum=2` 已被**分布式矩形覆盖**占用。**新算法若集成，应使用 `algNum=3` 起**（避免与现有 case 冲突，
> 这一点之前的设计文档需更正）。

## 0. 评判一个全覆盖算法的标准

先立标尺，否则"更优"无从谈起。好的全覆盖算法应同时满足：

1. **完备性 (completeness)**：可达自由区域 100% 被覆盖，不漏扫。
2. **低重复 (non-overlap)**：理想重复率趋近 0；工程上 < 10~15% 即可接受。
3. **路径平滑 / 少转向**：转向最慢、最耗能、定位误差最大，转向次数应尽量少。
4. **鲁棒**：对地图噪声、窄通道、非凸形状、定位漂移不敏感。
5. **可分解 / 可并行**：能切给多台车协同，且切分后仍满足 1~4。
6. **在线能力**：地图未知或会变时，能边走边规划（frontier 驱动）。

现有三套算法在这把标尺上的得分（详见仓库评审）：牛耕法弱在 1/2/4，STC 弱在 2，矩形覆盖弱在 4/5。
下面按"由易到难、由静态到动态、由单车到多车"四层递进。

---

## 第 1 层：把弓字形做对（BCD 牛耕分解）

**核心**：用障碍把可行区切成"每列单段连续"的子区(cell)，每个 cell 做一次性弓字，cell 间用 A\* 连接。
（完整设计见 `covering_alfor/docs/全覆盖算法-新算法设计-BCD牛耕分解.md`。）

**为什么它是基线最优**：
- 完备性：按障碍分解，逐 cell 扫净，天然 100%。
- 低重复：每条扫描线只走一次，cell 内零重复；唯一开销是 cell 间连接的空驶。
- 形状：直接在占据栅格上工作，支持任意非凸、带内部障碍——根治旧算法"只支持凸四边形"的局限。

**它还不够好的地方**（引出后面几层）：
- cell **访问顺序**只是简单按列排序，cell 多时 cell 间空驶可能很长。
- 弓字**方向固定**（竖直），房间横长时转向过多。
- 是**离线**算法，依赖已建好的静态地图。

---

## 第 2 层：cell 排序当作 TSP / 弓字方向自适应

### 2.1 cell 访问顺序 → 广义 TSP

把每个 cell 的"入口/出口端点"抽象成图节点，cell 间 A\* 距离作为边权，求一条**遍历所有 cell 的最短路**。
- 规模小（cell 通常几个~几十个）→ 可用精确 DP（Held-Karp，O(k²·2ᵏ)，k≤~15 秒级可解）或贪心+2-opt 近似。
- 每个 cell 有两个可选进入端（弓字可从上端或下端起步），属"广义 TSP (GTSP)"，把端点选择并进搜索。
- 收益：cell 间空驶里程显著下降，尤其在多房间/多障碍场景。

### 2.2 弓字方向自适应

弓字方向应让**扫描线垂直于子区的最长边**，使每条线尽量长、转向尽量少。
- 对每个 cell 求最小外接矩形 / 主方向（PCA 或旋转卡壳），按主方向定弓字朝向。
- 不同 cell 可用不同方向，cell 内统一即可。
- 收益：转向次数与定位累计误差同时下降（呼应标准 3）。

> 第 2 层把 BCD 从"能用"提升到"路径短、转向少"，是单车静态场景的**实用最优**。

---

## 第 3 层：真正的生成树覆盖（Spiral-STC）作为对照/补充

现有 STC 退化成"DFS+回溯"，重复率 ~100%。**真正的 STC** 值得作为 BCD 的对照与某些场景的补充：

- 把地图按 **2D×2D**（D=机器人半幅）粗格分块，每个粗格再分 4 个 D×D 子格。
- 在粗格上建生成树，机器人**沿生成树的"墙"绕行**（circumnavigation）一圈。
- 数学保证：每个 D×D 子格恰好被经过一次 → **零重复、完备**，且路径天然连续、几乎不掉头。

**与 BCD 的取舍**：
| | BCD（第 1~2 层） | Spiral-STC |
|---|---|---|
| 重复率 | 低（cell 间空驶） | 极低（理论 0） |
| 路径形态 | 弓字 + 跳转 | 单条螺旋回路，几乎不掉头 |
| 对窄道 | 原分辨率，友好 | 受 2D 粗格量化，窄于 2D 会被堵 |
| 实现复杂度 | 中 | 中高（绕行/子格映射易错） |

结论：**静态规则房间用 BCD+TSP；空旷大场地、追求最少掉头用 Spiral-STC**。两者可按场景切换，而非二选一。

---

## 第 4 层：在线 / 未知 / 动态环境 —— frontier 驱动 + 局部重规划

前三层都假设"地图已建好且静态"。但本项目是**边建图边覆盖、且有第二辆车在动**，必须有在线能力：

### 4.1 frontier-based 在线覆盖
- 不预先要求完整地图：维护"已覆盖/未覆盖/未知"三态栅格。
- 每步选最近的**覆盖前沿 (coverage frontier)**——已覆盖区与未覆盖自由区的边界——作为局部目标，
  局部用弓字推进，撞到新障碍就地更新分解。
- 地图扩张时增量维护 cell，不全量重算。

### 4.2 动态障碍（另一辆车）单独成层
- **关键原则：动态障碍绝不写进静态覆盖地图**（否则另一辆车走过的地方被永久标记为"墙/已覆盖"，
  造成漏扫和幽灵墙——这正是双车出 bug 的根因之一，详见 `03-双车分布式建图与全覆盖bug分析.md`）。
- 维护两张图：**静态覆盖图**（只受确认的静态障碍影响）+ **动态层**（对方车实时位姿，短时效）。
- 规划在静态图上做；执行时用动态层做局部避让（已有的 `COOP_AVOID` 通道可作为动态层数据来源）。

### 4.3 局部重规划
- 当对方车阻挡当前弓字线时，不是停死等（现状），而是**临时跳到同 cell 的下一条扫描线**或邻接 cell，
  回头再补这条线——把"等待"变成"先干别的"，吞吐更高。

## 第 5 层：双车协同覆盖的"正确"分解（面向本项目）

现有"把一条 roadFile 对半砍、两车从两端相向而行"的做法有结构缺陷（两车在中点相遇、依赖两端读到同一文件，
详见 bug 文档）。更优的协同分解：

### 5.1 空间分区而非路径对半
- 先对整个可行区做 BCD 分解，再把 **cell 按面积/里程均衡地分给两台车**（图分割 / 贪心装箱），
  让两车覆盖**空间上分离**的区域 → 天然减少相遇与协同避障开销。
- 分配以"工作量均衡 + 边界最短（减少交界处冲突）"为目标。

### 5.2 同一坐标系是前提
- 两车必须在**同一地图坐标系**下分配与执行。现状靠"同物理起点同朝向 + HTTP 拉同一张图"维持，非常脆弱。
- 更优：一台车建图并广播地图 + 两车各自做**重定位 (relocalization)** 到该图，得到各自在**统一世界系**下的位姿，
  再分配 cell。这样两车不必从同一点出发。

### 5.3 协同避障作为兜底而非主力
- 空间分区做好后，两车很少相遇；`COOP_AVOID` 只在交界带偶发触发，回到"少数情况下的让行"，
  而不是现在"频繁触发 + 状态机易死锁"的主力机制。

---

## 思考小结（持续更新）

| 层级 | 方案 | 适用 | 相对现状的提升 |
|---|---|---|---|
| 1 | BCD 牛耕分解 | 静态规则/非凸房间 | 完备 + 低重复 + 任意形状 |
| 2 | + cell-TSP 排序 + 方向自适应 | 多房间/多障碍 | 空驶里程↓、转向↓ |
| 3 | 真 Spiral-STC | 空旷大场、最少掉头 | 重复趋零、路径连续 |
| 4 | frontier 在线 + 动静分层 | 边建图边扫、有动态障碍 | 不漏扫、无幽灵墙、不停死 |
| 5 | 空间分区协同 | 双车 | 两车空间分离、避障变兜底 |

**推进建议**：先落地第 1~2 层（单车把覆盖做对做优，可用独立 demo 量化验证），同时把第 4.2 的"动静分层"
作为**纪律**贯穿（哪怕单车阶段也别把动态障碍写进覆盖图）；双车阶段直接上第 5 层的空间分区，而不是继续打磨
"路径对半 + 相向而行"。
