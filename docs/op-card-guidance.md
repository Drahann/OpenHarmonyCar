# 操作卡分步引导（"下一步该干嘛" 补全）

> 用户：照"连接/建图"那条主线的标准，把 astar / fullpath / distributed 三种操作卡也逐屏过一遍，
> 每一步都给明确指示——目标是操作者任何时候都知道"下一步该干嘛"。**先写本文档（设计），再实施。**
> 代码：`app-harmony/.../pages/ControlPage.ets` 的 `AstarOps`/`FullpathOps`/`DistributedOps` + 文案 helper。

## 通用原则
- 每张操作卡顶部一行**分步指示**（①②③…），随状态推进。
- 动作按钮的可点/禁用已按实时心跳门控（见 `safety-flow-review.md` §1）；引导文案解释"为什么现在能/不能点下一步"。
- 命令下发已有 toast（"已下发…"），见 `safety-flow-review.md` §7。本轮补的是**卡内的步骤态文案**。
- 真实执行态（到达/完成）UDP 无 ack（Q1）→ 文案只说"已下发/进行中"，配合心跳位姿/进度条间接反映。

## 1. astar（单点导航）
分步：**① 点地图选目标点 → ② 点「开始导航」**（导航中可取消 / 重新选点）。

| 状态 | 顶部指示 | 目标点显示 | 按钮 |
|---|---|---|---|
| 未选点 | `① 点地图选目标点 → ② 点「开始导航」` | `点地图选点` | 开始导航**禁用**（无目标） |
| 已选点 | `目标已选 (x,y) · 点「开始导航」` | `(x,y)` | 开始导航**可点**（连接正常时） |
| 导航中 | `导航中…（点「取消」停止；到达后可重新点图选点）` | `(x,y)` | 「重新导航」+ 取消 |

- 新增 `@State astarNavigating`：`startAstar` 置 true；`cancelRoute` / 在 astar 模式重新选点 置 false。
- 导航中无"到达"信号（Q1）→ 文案不谎称"已到达"，靠地图上机器人 pin 移动看进度。

## 2. fullpath（单车全路径覆盖）
分步：**① 选覆盖算法 → ② 点地图选 4 顶点（左下→右下→右上→左上）→ ③ 满 4 自动启动**。

- 算法区上方加标签 `① 选覆盖算法`（牛耕 / 最小生成树，对应 cmd102 byte1）。
- `fpHint()` 带步号：未满 4 → `② 点地图选第 N/4 个顶点（左下/右下/右上/左上）`；满 4 → `③ 4 顶点已选，全路径覆盖已启动（点「停止」结束）`。
- 「重选顶点」清空重来；「停止」结束覆盖（cmd103）。

## 3. distributed（多机协同覆盖）
分步：**① 选下发方式 → ② 点地图选两对角点划区 → ③ 看各车覆盖进度**。

- 下发方式上方加标签 `① 选下发方式`；开关文案点明区别：
  - 开 = `经车载 agent（黑板·各车自主覆盖）`；关 = `平板直发（兜底·直接发本车）`。
- `distHint()` 带步号：未选 → `② 点地图选两个对角点划分覆盖子区域（对角矩形）`；已选 1 点 → `② 已选对角点1，点第二个对角点完成子区域`。
- 进度区上方加标签 `③ 各车覆盖进度`（进度条）；进度暂由 agent 回写黑板（无 agent 时恒 0，已知）。
